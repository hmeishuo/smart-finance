# Smart Finance｜AI 智慧個人財務管理系統完整開發需求 Prompt

## 一、專案角色與目標

你是一位資深全端工程師、系統架構師、資料庫設計師及 AI 應用開發工程師。

請協助我從零開始開發一套名為 **Smart Finance** 的 AI 智慧個人財務管理系統。

這不是單純的記帳網站，而是一套整合網站、LINE Bot、自動記帳、AI 消費分析、帳戶管理及預算規劃的個人財務管理平台。

我的目標是讓系統可以自動取得消費資料、辨識交易內容、自動分類及記帳，並透過 AI 主動分析個人消費習慣，減少手動記帳的時間。

請以真正可以長期使用、可以部署上線的產品為開發目標，而不是只製作展示用的 Demo。

## 二、基本開發條件

- 專案名稱：Smart Finance
- 使用對象：個人自用，單一使用者為主要設計方向
- 開發環境：Windows
- 使用裝置：電腦、手機及平板
- 網站形式：RWD 響應式網頁
- 語言：繁體中文
- 預設貨幣：新台幣 TWD
- 開發預算：盡量使用免費或低成本服務
- 部署方式：雲端部署，確保電腦關機時仍可正常使用
- 系統整合：網站與 LINE Bot 共用同一套後端 API 及資料庫

網站必須可以獨立運作，不可以依賴 LINE 才能使用。LINE Bot 也必須能獨立提供聊天記帳及基本查詢功能。

網站與 LINE 之間的資料必須即時或透過可靠同步機制保持一致。

### 3. AI 自動記帳系統

這是整個系統最重要的核心功能。

系統需要支援六種資料來源：

（1）銀行及信用卡交易同步
- 取得銀行及信用卡交易紀錄。
- 自動辨識交易金額。
- 自動辨識交易日期。
- 自動辨識商家。
- 自動分類。
- 自動對應帳戶。

銀行資料必須透過合法授權的 API 或金融資料服務取得，不可直接爬取網銀或儲存網銀密碼。

第一階段先支援 CSV／Excel 帳單匯入，後續再擴充銀行串接。

（2）電子郵件解析
- 支援 Gmail。
- 研究 Outlook 擴充方式。
- 使用 OAuth 授權存取信件。
- 辨識銀行消費通知。
- 辨識信用卡交易通知。
- 辨識電子收據。
- 自動解析交易日期、金額、商家及付款方式。
- 避免重複解析相同信件。

不得保存使用者的 Email 密碼。

（3）OCR 收據辨識
- 上傳收據圖片。
- 上傳發票圖片。
- 自動辨識商家名稱。
- 自動辨識交易日期。
- 自動辨識總金額。
- 辨識商品明細。
- 自動分類。
- 儲存原始圖片。
- 允許使用者修改辨識結果。

（4）AI 聊天記帳
支援網站及 LINE 文字輸入。

例如：
- 午餐 120 元
- 今天搭車 35 元
- 昨天買衣服花了 1500 元
- 收入 5000 元，工讀薪資
- 今天跟朋友聚餐 450 元，刷信用卡

AI 必須自動解析：
- 交易類型
- 金額
- 日期
- 分類
- 商家
- 帳戶
- 付款方式
- 備註

如果資訊不足，必須詢問使用者，不可以自行編造資料。

（5）Excel／CSV 匯入
- 支援批次匯入交易紀錄。
- 提供欄位對應功能。
- 支援日期格式轉換。
- 支援金額格式轉換。
- 匯入前預覽。
- 重複資料檢查。
- 匯入錯誤提示。

（6）台灣電子發票整合
- 研究財政部電子發票相關 API。
- 評估個人載具資料授權方式。
- 取得合法授權後才進行串接。
- 解析發票日期、金額及商品明細。
- 發票資料與銀行交易進行比對。
- 避免重複入帳。

### 4. 統一交易處理中心

所有來源取得的資料都必須經過同一個交易處理流程。

處理順序：

1. 接收原始資料。
2. 資料標準化。
3. AI 辨識交易內容。
4. 自動分類。
5. 帳戶對應。
6. 重複交易檢查。
7. 資料完整度檢查。
8. 判斷是否需要人工確認。
9. 建立正式交易。
10. 更新帳戶餘額及預算。
11. 更新 Dashboard。
12. 提供 AI 分析資料。

採用「固定規則優先、AI 輔助」的方式，減少 AI 錯誤及 API 成本。

高信心度的交易可以自動入帳；低信心度、資料不足或帳戶不明確的交易，必須進入待確認區。

所有自動交易必須具有來源識別碼及防重複處理機制。

不代表當次必須執行的任務。

實際開發範圍、執行順序及允許修改的內容，
以使用者當次確認的任務為準。

開始任何開發任務前，請先：
1. 說明你對該任務的理解。
2. 列出需要確認的問題。
3. 提出實作計畫與驗收標準。
4. 等待使用者確認後，再開始實作。

未經確認，不要直接開始全部功能的實作。

每完成一個小任務，請提供：
- 完成內容。
- 新增或修改的檔案。
- 實際執行的測試及結果。
- 尚未測試的項目。
- 需要使用者操作的步驟。
- 已知問題與下一步建議。

未經使用者驗收確認，不要自動進入下一個任務。

**最重要的原則：先建立穩定、正確、可運作的核心系統，再逐步擴充 AI 與自動化功能。**
